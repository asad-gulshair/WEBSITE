## Contact buttons (what each one does)
- **Start a project** (header, mobile menu, hero, About, CTA bands, "Start a similar project" in case studies) → `contact.html#start`:
  scrolls to the contact options and briefly highlights them. It never opens a mail client or any webmail/Google page.
- **Email me** → plain `mailto:` (subject "Project enquiry"), opens the visitor's default mail app. **Copy email** copies the address
  and shows "Copied". No Gmail compose URLs anywhere.
- **Book a meeting** (header, mobile menu, hero, How to connect, CTA bands, Contact) → opens the "Let's talk" guide below.
- **LinkedIn** (Contact card, footer, guide) → https://www.linkedin.com/in/asad-gulshair in a new tab.

## Book a meeting ("Let's talk" guide)
Every "Book a meeting" button opens an accessible dialog (`assets/js/meet.js`): focus moves into it, Tab stays inside, Esc / the ×
button / a click on the backdrop close it and focus returns to the button. On phones it is a bottom sheet. A small inline SVG shows
three routes from you to a call; it is static for reduced motion. Three cards:
1. **Book a Google Meet call**: `content/site.json` → `contact.bookingUrl`.
   - Empty (default): "Request a call" opens an email to asadgulshair6767@gmail.com, subject "Meeting request - project discussion",
     with a body asking for 2-3 preferred times (with timezone) and a short project summary.
   - Set to a Calendly / Cal.com / Google Calendar appointment-page URL: "Pick a time ↗" opens it in a new tab.
2. **Connect on LinkedIn**: `contact.linkedinUrl`, new tab.
3. **Email**: the address, **Copy email** (shows "Copied") and **Email me** (mailto).
Without JS, or with Ctrl/Cmd-click, the button is a plain link: the booking page, or the pre-filled meeting email.

## Enquiry form (client capture)
`assets/js/leads.js` renders the form into every `[data-lead-form]` (full form on `contact.html`, quick form in the contact band on Home, Work and About).
- **Delivery:** POST of JSON to `contact.formEndpoint` in `content/site.json` (admin panel: Site settings > Contact > Enquiry form endpoint).
  - *Google Apps Script (recommended, free, Sheet + email):* paste `tools/lead-capture.gs` into a new script at script.google.com, run `setup` once, deploy as Web app (Execute as: Me, Access: Anyone), paste the `/exec` URL into `formEndpoint`. Each enquiry becomes a row in a "Portfolio leads" Google Sheet, you get an email (reply-to = the visitor) and the visitor gets a short confirmation.
  - *Formspree:* paste the form URL (`https://formspree.io/f/xxxx`) into `formEndpoint`.
- **Empty endpoint (default) or a failed send:** the form opens a pre-filled email to you instead, and offers "copy the message", so an enquiry is never lost. It only says "Thanks" after a confirmed send.
- **Spam:** hidden honeypot field, 2.5 s minimum fill time, 15 s cooldown per browser.

## Editing with the admin panel (Pages CMS)
Free, GitHub login, no server. There is deliberately no admin button on the public site.

4. Each Save is a commit to `main`; GitHub Pages republishes in 1-2 minutes. Refresh the site (a hard refresh if your browser

## Deviations from REFINE_SPEC.md
- **Multi-page** (owner request): Home / Work / About / Contact instead of one long page. The category navigation of §5 lives on the
  Work page (sticky category bar under the header); the home "practice index" previews the morph on hover and links to `projects.html#<cat>`.
- **No bundler, no Lenis, no pmndrs postprocessing.** Bloom is replaced by a soft additive halo on the accent ring; vignette by CSS.
  SMAA → native MSAA. Native smooth scrolling with a measured header offset.
- **Glass element:** fresnel/coating shader on all tiers (no transmission pass), to stay inside the frame budget and keep
  video capture fast. Anisotropy is one rotation for all blades (instanced material).
- **Low tier / no WebGL:** one pre-rendered still (`hero-still.webp`) instead of five AVIF state renders.
- **Fallback illustrations are SVG**, not build-time 3D renders.
- **Case studies** use the in-page `<dialog>` and `#/work/<slug>`; no prerendered `/work/<slug>/` pages.
- **Badge "CURRENT ROLE"** marks work from the current job whose code is private (not in the spec's list), so nothing is overstated.
- **Detections in the tomato loop** are drawn per frame in Python (thin 2px boxes, dark mono label chips) instead of a live SVG
  overlay; real output frames from repos/videos keep their original annotations.
- **IEEE paper is linked** (owner request). Note: IEEE Xplore lists author affiliations, which shows the university.
- "I usually reply within a day" follows the owner's wording. "Available for new projects" is a default: edit or clear `contact.availability` in `content/site.json`.
